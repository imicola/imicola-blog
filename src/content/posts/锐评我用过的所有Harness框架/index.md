# 目前主力使用

*imicola* 目前还在主力使用的框架主要是御三家中的 ChatGPT 和 Antigravity，同时国模上使用的是 Zcode , dsh , Workbuddy (刚刚弃用)，Qoder (学生免费会员过期后就不用)，同时也在用 pi 与 omp

## ChatGPT

*GPT 专武*

稳定性的神，搭配 GPT 使用几乎不会在任务上出现问题,自动审查模式配合 /goal 非常好用, Computer Use 和 Web Use 在 Windows 会和你抢鼠标并且非常耗费额度，建议非必要不用，无头浏览器其实挺好用了。同时 ChatGPT Work 下似乎不会打开内联的浏览器做审查而是更加偏向无头浏览器。

主要问题是，因为是 GPT 专武,对其他家的模型适配不是很好，经可能或多或少会出现一些问题，还是需要搭配自家的模型才好用，虽然 OpenAI 不够 Open 已经是常有的事情了

---

## Zcode

*不错的开箱即用 Agent Harness*

虽然之前 Zcode 暴雷了，但是 *imicola* 一直在坚持不懈的使用 (:spoiler[才不是因为 imicola 有嘎啦嘛家的 plan,然后在 Zcode 里有1.5倍的额度优惠呢]) ,抛开这些来说，Zcode 的 Harness 设计的确实不错，内置了很多 Agent 工具，自动化浏览器与 computer use等,远程链接体验也非常完善，每天晚上还会发3亿的 glm5.3f 的 token,虽然因为 *imicola* 学校 11 点断电准时和鸡蛋时间错开导致一次都没用过(

Zcode 团队在长程任务的编排上似乎是下过功夫，跑一个很复杂的工作的时候，Agent 不会忘记目标,非常省心;总的来说，如果需要一个开箱即用的 Harness ,Zcode感觉是一个不错的选择。就是之前用Zcode做长程任务的时候，做到后面页面特别卡,不知道经过现在的迭代后会不会好一些

## Antigravity

*有点难用(*

说实话，如果不是咕噜咕噜对 Agy 的反代的超级无敌雷霆狂杀，我感觉没有什么人愿意使用 Agy(, 奈何 Agy 里的氢猫真的很好用,而且额度给的很大方，Agy 拖氢猫后退了!

Antigravity 如同一个标准的互联网超级巨人生产出来的产品，以稳定性与健壮性为主，反而失去了作为 Harness 框架最重要的精神，就是充分发挥模型能力，你可以在 Agy 里看见很多一眼看过去很厉害的功能，agy的打出 `/` 后蹦出来的菜单是我见过最长的，有一些一眼看过去很有潜力的功能，比如 `/swarm` 和 `/teamwork`，这种大型的 Agent 集群功能；但是奈何 Agy 底层设计太难绷了，Agent 使用的 终端实例 是电脑本机不隔离的，是直接带上 profile 的，是没有生命周期的。经常见到任务跑完了还有几十个终端实例在跑...

还有比较神秘的就是，它的搜索，在 *imicola* 电脑里已经有 wsl grep + pwsh7 rg 的情况下，它居然，**居然一个一个的读文件来找自己需要什么!!!** 感觉就和谷歌在炫耀自己家模型的能力一般

## Workbuddy

*有点神秘*

听说 Workbuddy 的底层 Harenss 走的是 Claude Code 路线的设计，但是走 Claude Code 路线设计不太可能；*imicola* 为了白嫖积分而使用 wb ,在体验感觉上只能算是 「能用」的梯队，但是似乎模型能力在 wb 框架下会有所削弱，wb 上的 *DeepSeek-v4.1flash-1017* 能力似乎不如在轻度插件支持下的 dsh 中的表现；据我观察，wb 中的模型，惰性似乎都很强，想要达成一个好的效果可能需要专门斟酌一下提示词

wb 虽然积分给的很多，但是每天每个模型有一个调用上限，似乎是1亿 token，所以如果想干超大任务与长程任务的话，wb反而不太适合；底层的 Harness 设计似乎一般般，没有过多亮眼的设计，前端样式似乎也有bug，在执行任务的时候直接发送调整指令，会让流式输出卡住,反正挺诡异的。而且不知道 wb 是不是为了让办公人群也能用明白，将很多 tool use 的细节隐藏了，导致我有时候没办法通过模型的调用内容与 tool 返回判断模型是不是在干一些很神秘的事情 :spoiler[就比如说之前有一次在用 wb 的时候，模型没找到本机的 browser-agent，然后尝试调用机器上的 chrome 的调试模式自己写极简工具去调用截图]

## Trae

*似乎不错*

新版 Trae 没怎么深入体验过，但是很久之前(似乎是在哈基米2.5Pro)时代，用过很长一段时间的 Trae

之前的 Trae 还是在那个 IDE 插件漫天飞的产物，*imicola* 使用国际版 Trae 完成了人生中第一个较为完整但是非常粗糙的全栈 vibe coding 项目 [imicola/notebit](https://github.com/imicola/notebit) 

放到现在焕然一新的 Trae 来看，我感觉应该是目前国内大厂产品下做的最出色的一个了，整体的 tool call 错误率比较低，同时也内置了产品内联的浏览器，并且做了深度适配；而且 Trae 送的积分也挺多的说是，并且最重要的是似乎没有每天限制，但是会在高峰期遇到模型排队的现象，可能整体时间完成的时间上稍微慢一些

但是我没有使用 Trae 做过长程任务与超大型任务，Trae 中的模型派发 subagent 的意愿似乎也不高，所以我不太好说在大型仓库与任务面前这个 Harness 基座是否能有很好的发挥

## Qoder

*你问 Qoder 好用还是难用，Qoder 好难用是什么意思?*

**阿里到底会不会做产品？**

*imicola* 为了打阿里组织的天工开物的比赛，深度使用了大概一个星期的 Qoder, 由于 *imicola* 的学生优惠券都拿去买服务器了，且自己的账号不知道为什么没办法领取第一个月 Qoder 的20块钱优惠，所以一怒之下斥巨资在新账号下购买了 Qoder Pro。

深度用下来，Qoder如同一个大号 Agy，有很多一眼看过去非常优秀的设计功能， `repo wiki` 和 知识库 都是其他家少见的功能，同时前端设计很不错，第一眼很有使用的欲望

但是这种使用欲望会在使用 qoder 正式跑一次任务后被摧毁的灰飞烟灭；不知道为什么，在 ds 拥有 200-300 tps吞吐量的情况下，等待一个任务的完成也非常非常久；个人体感下在 Qoder 中完成一个同类型任务的耗时比在其他 Harness 里慢了至少 40%，同时底层工具调用感觉完全没有优化测试过，在 ds 拥有 384K tokens 最大输出的情况下，居然会在 Qoder 中因为超出这个输出限制而被戒断(?)

Qoder对工具的打磨也非常神秘，举个简单例子，一般的 harness 工具在打磨 write 这个工具的时候，如果模型在对话上下文中从来没有读取过一个已经存在的文件，那么 tool 就会阻止这次的写入并且强制要求模型读一次文件 ，防止模型因为 「自信写入」与神秘幻觉，出现低级的错误问题；但是 Qoder 的 Harness 就给 Agent 提供了一个 *非常舒适的环境*，LLM 想怎么改就怎么改.jpg ,这导致 Qoder 总是在 LLM 进行到后期走全量测试与编译的时候才会将文件错误暴露出来，即浪费了时间也消耗了额度...

再说说子代理的功能，似乎只有在使用 Qwen 模型的时候, Qoder 才会愿意将 subagent 单独放在一个空间跑，而我使用 ds 的时候，经常就是直接在对话上下文中召唤3个子代理，然后三个子代理跑个300秒左右准时下班，然后主 Agent 才继续往下走,同时，对于长时间的终端任务，Qoder 里的模型将其放到 background 中的意愿也很低，就干等一个编译，一个测试跑完，然后美美吃上 pwsh 的神秘报错

再说到优化问题，harness 产品在流式输出下前端界面渲染压力大，有卡顿是常见的事情，从DeepSeek Harness，Zcode 到 ChatGPT 都没办法做出特别好的优化，但是你 Qoder 呢? 在让人完全看不懂现在模型在干什么的情况下，不仅前端有卡顿，使用 Qoder 的时候，整个电脑都会卡卡的...什么感受呢，你给 Zcode 甩了一个 goal，然后将它最小化到任务栏里，Zcode会停止前端的渲染释放压力，同时后端的 Harness 压力并不大，虽然会吃一些内存，但是整个电脑流程运行还是没问题的；但是 Qoder 在前端页面卡的要死的情况下，会连带着让整个电脑变得无比卡顿，在配合 Qoder 那超级无敌长的任务进行时间，就让 Qoder 在跑任务这段时间使用电脑是一种折磨...

最后再说这个性价比的问题，Qoder 的产品是唯一一个我在国内御三家(腾讯，字节，阿里)中花了钱的产品，然而 Qoder 给我的反馈就是我以后再也不会订阅他们家的产品了；一个全栈项目MVP做下来，就花费了会员 2000 积分中的一半，再加上打磨，测试，部署，整体下来没 2 天 Qoder 的积分就消耗完了；而这个会员，除了每个月比普通用户多 2000 积分，site 比普通用户多一些权益外，基本没有更多更好的权益了；同时阿里家的这个订阅，就如同原价买 API 一样，基本没有任何的折扣优惠；那么问题就来了，我在有更好的工具，更便宜的订阅下，我为什么要选择你们家的产品?订阅没有性价比，而工具做的让人一言难尽...有一种来自大厂下的傲慢内核...

## DeepSeek Harness

*潜力极大*

DeepSeek Harness(dsh)，深度求索官方 Harness，大肥鱼指定专武， :spoiler[其实感觉在只使用单个Agent实例的情况下没有 omp 强] ，想定制什么功能自己做.jpg。插件式的架构让其一开始就不可能作为一个开箱即用的 Harness 进行，但是好在 ds 的热度足够高，ds 官方足够支持开源生态。让 dsh 插件生态拥有无与伦比的活力

作为一个全方向的 Harness 来说，dsh 应该是打不过类似 cc，omp，codex这种老牌选手的，但是 dsh 最大的最大的优势就是，每个人都可以做自己的 Harness，dsh 是一种越用越顺手的 Harness，同时也是社区极其庞大的 Harness ，我相信在这种环境下，dsh 的发展肯定是勃勃生机万物竞发的生态景象的

但是对于肥鱼这种性格的AI来说，在一个高智商模型的安排下进行集群合作是能最大规模展现能力的场景，而在 dsh 中，这种场景可以被 「智能体团队」 的官方插件实现，而且效果非常不错

---

## pi and omp

*有点神*

pi 是一个更加极端的 dsh，本身只有四个标准工具能够调用，真正的做到了 「极简」 主义的 harness，在 Linux 下更是超级好用；*imicola* 的 Linux 作业需要交 4 份视频，而 *imicola* 非常懒惰不想自己弄，于是就在 pi 中丢下了一句「帮我做好四份Linux作业并且打包好需要上交的内容，本机有 OBS , 」就不管了，然后在 20 分钟后，ds 只花费了 0.8CNY 的消费，就将所有的东西都扔给我了。

omp 则更类似 pi 的威力增强版，在 pi 的基础上加入了很多人见人爱的功能，比如 plan，goal，loop 等功能，对单个 LLM 的实力可以发挥的很充分。

同时因为终端 Agent ，在前端渲染压力和 Agent 压力下，本身非常轻量，对系统的开销比较小(:spoiler[但是为什么 codebuddy CLI在终端里那么卡]),所以使用起来也是非常不烧心的

# 使用过一段时间
## OpenCode

*终端Agent白月光*

一切都要从 claude code 自爆「开源」说起，opencode 诞生了，而恰逢此时 Zcode 还没诞生，*imicola* 手里还有嘎啦嘛的 Coding Plan 可以用,在被 A\ 理念气笑了的 *imicola* 从 ClaudeCode 怒而转向 OpenCode 中；美妙的 TUI 界面 , 极客般的配置，同时加上 *oh-my-opencode* 插件的威力增强，使得 Opencode 成为 *imicola* 终端 Agent 的白月光。

但是具体要说好不好用吗，那真不一定有多好用; Opencode 原生框架非常的毛胚房，模式上只有 plan 和 build 两种模式，底层的 Harness loop 与 cc 的很像，但是 cc 好用的前提是用 claude，其他模型可能会比较 「水土不服」，所以 oc 用了一个很聪明的解决方式，就是 *精简化*，能让大多数模型在一个较为平均的水准下 work；

而加入了 *oh-my-opencode* 的 oc，就如同模型能力放大器，omo 的策略是比较激进的调用子代理完成任务，并且根据不同的任务分发不同的子代理，这在一个 「有钱人」手上是非常吃香的，规划调用用 SOTA，苦活累活用一线模型；但是对于我们这种手里一般只有一家厂商 plan 的普通人来说， omo 的调度就有些过于激进了，对额度消耗的很快，而完成的任务说不定不如一个模型单线进行的优秀多少

## Claude Code CLI

*标杆*

严格来说，Claude Code CLI 是我使用的第一个纯 Agent Harness 产品，作为编程产品领域的 GOTA Anthropic，虽然在公司风格和价值观这块不受大部分国人待见，公司本身也是处于神鬼二象性的神秘状态下。但是无可否认的是，A\ 确实开辟很多产品与 Agent 概念的先河

cc 作为这么一款老牌产品，本身性能被调教的足够优秀，对自家模型的适应非常成功，乃至于成为很多 Agent 的底层借鉴设计。可以说 cc 已经可以作为 Harness 的标杆了，就和很多成熟优秀的产品一样。

~~但是 cc 的 TUI 不好看，所以我不用它~~

## Vscode Copilot

*不好评价*

怎么评价 Copilot 呢? 在 Harness 发展出来之前，Copilot 在 LLM Coding 领域几乎是无可挑剔的；在坐拥 *GitHub* 超级无敌大仓库的优势下且计费政策改版之前的两年免费学生认证 Pro 来说，Copliot 以碾压的姿态胜过了市面上的编程产品，可是随着 Harness 的发展，Copilot 的能力似乎越来越更不上主流 AI Coding 产品了，并且随着 Claude Code 的推出，人们开始逐渐向无代码发展

Vscode Copilot 最近也是在不断跟上时代，也出了 CIL 与自己的 独立智能体框架，但是反正我已经从 copliot 中脱离出来了，并且这个新的会员体系也将学生可以使用的 LLM 砍的所剩无几，自然也就没有使用 Copilot 的动力了
